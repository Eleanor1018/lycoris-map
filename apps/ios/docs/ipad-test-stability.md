# iPad 自动化交互故障排查（2026-09-22）

## 失败证据与修复

上轮完整矩阵共 19 项 UI 测试，首次通过 15 项。保留原始失败结果，没有将重复运行中的成功片段拼成一次全绿执行。

- 登录后编辑失败时，系统“保存密码”弹窗仍覆盖贡献表单。原辅助函数只点击一次“以后”就继续检查编辑器。现在限定在包含该按钮的系统 Alert 或 Sheet 中查找，等待整个弹窗消失；最多尝试三次，仍未关闭就截图并失败。没有关闭密码自动填充，也没有改动账号或编辑业务。
- 最大辅助字号测试在 Settings 的 About 行出现前等待该行存在。原生 Form 会延迟创建屏幕外的行。现在先确认设置弹窗打开，再在明确标识的 Form 内滚动，仍要求 About 和 Done 可点击，且 Done 必须实际关闭弹窗。
- 原方向初始化发生在应用启动前，结束时可能恢复成 Unknown。现在先终止上一用例的应用，再设置初始方向；默认启动后明确确认实际竖屏窗口，再旋转并等待真实窗口宽高匹配。清理时先终止应用再恢复有效方向，避免把恢复事件发送给上一用例的场景。方向前置条件失败会立即结束用例，避免后续点击产生连锁误报。

13 英寸复测中曾出现设置入口点击没有打开页面，11 英寸复测也曾出现搜索框没有取得焦点。录屏和事件坐标不足以证明应用坐标错误；不能把这些现象直接归因于模拟器或 SwiftUI。新增左右横屏冷启动测试，启动后只观察窗口尺寸，不再补发方向事件；随后单次点击输入查询、打开并关闭设置，检查搜索文字保留。

应用代码只给设置 Form 增加稳定的无障碍标识，没有修改布局、登录或编辑逻辑。原有查询、收藏、详情、草稿、旋转、可点击性断言均保留，没有跳过失败用例。

补充 iPhone 回归时，新建标签用例也复现同一问题：点击“以后”后，AX 与最终截图仍显示“保存密码？”Sheet，导致底层选点入口不可点击。iPhone 的提示类型与 iPad 不同，因此将两个测试套件的密码提示处理统一到 `LocalBackendTestCase`，同时覆盖 Alert / Sheet，并复测两个尺寸 iPad 的登录收藏、编辑草稿及 iPhone 全部七项回归。该轮失败的 xcresult 与截图原样保留。

新建 13 英寸模拟器的对照检查进一步确认两处等待问题：

- 密码提示先挂载空的远程视图，8.59 秒后才明确显示标题与按钮。只对 App 等三秒、再对 SpringBoard 等三秒，会漏掉晚出现的 App 提示。现在在一个 10 秒窗口内持续检查两个宿主；找到后按容器自身类型和标签等待消失，避免按钮先消失造成误判。
- 关闭分享后，背景详情标题仍存在，不能证明分享已经关闭。录屏显示接下来的侧栏点击仅收起了残留分享 popover。现在最多三次尝试关闭原生分享，必须确认关闭控件消失、详情恢复可点击，才继续旋转和点击侧栏。未改变应用自己的侧栏关闭行为，也未增加应用按钮的点击重试。

附近流程保留“先旋转到竖屏，再首次打开分享”的原路径；之后补充右横屏和左横屏的原生分享打开、关闭检查。分类结果、详情打开、分享打开和关闭后的可交互性都是强制前置条件；失败立即抛错结束，避免异步 XCTest 在第一个断言失败后继续生成级联错误。

## 尚未确认的间歇性现象

13 英寸的某些执行中，旋转后的首次点击没有带来预期界面变化。分享入口的临时日志证实，失败时没有进入 `onShare`；分类入口的另一次失败只确认仍停在首页，不能仅凭没有结果认定 action 没有执行。事件坐标和录屏显示点击目标正确且没有可见遮挡，目前无法确定根因在应用还是自动化事件链路。

将 Liquid Glass 改成不参与命中的背景后，三次重复仍失败一次，且首错发生在分类入口；该实验已撤回。随后增加临时 `UIWindow.sendEvent` / 焦点 / action 日志，三次原分享流程、六项完整 iPad 流程和三次三方向分享诊断均通过，没有取得新的失败触摸样本。这些成功不能证明原间歇性问题已修复，也不能证明玻璃效果或模拟器是根因。最终源码删除全部探针和方法交换，保留日志与失败证据，并从无探针产物重新运行完整矩阵。

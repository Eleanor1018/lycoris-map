# Rust 成为仓库与本地默认后端

日期：2026-09-14。Nora 确认范围为「先切换仓库和本地，线上暂不动」。温晓负责设计、指导与验收，苏瑶通过 OpenCode Go / DeepSeek V4.1 Flash 实现启动配置、测试与返工。

## 决定

- 正式开发路径继续使用 `backend-rust/`，Rust 默认端口改为 `8080`。Vite 默认代理到 `127.0.0.1:8080`，原生 App 的既有默认端口保持可用。
- `backend/` Java 退出默认开发流程，保留源码、产物路径和原运维配置，供现有线上服务及回退参考。不批量重命名目录或改写历史验收证据。
- 本地启动统一为 `python backend-rust/scripts/run-local.py`。启动器加载 `.env`，进程环境优先，固定 Cargo 工作目录并使用锁定依赖和 SQLx 离线元数据；普通启动不迁移数据库。
- 本地示例写请求白名单包含 Vite 默认 5173 端口。自定义端口必须显式配置来源，既有权限规则保持不变。
- 根中英文 README、架构、总览与 Rust 说明以默认开发状态组织；线上仍为 Java 的边界明确保留。测试与演练 Compose 的隔离端口不变。

## 验收要求

1. 启动器正确加载配置与传递维护参数，非法配置不泄露值，缺必填项明确失败；格式与相关 Rust 单元检查通过。
2. 通过正式入口在本机 8080 启动 Rust，健康检查通过；前端清除临时上游覆盖后，使用默认代理完成公开读取与登录写请求。
3. 当前合成演示数据复制到固定本地开发依赖，点位、用户、业务关系、迁移与媒体完整；旧演练副本保持可用，不删除或重置数据。
4. Java 不占用本地服务端口，线上配置与服务不变；本轮改动提交并推送到 `refactor/rust-backend`。

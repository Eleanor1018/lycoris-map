1. **Linux 发布基础**：精确工具链和容器镜像、离线 SQLx 的 release 构建、非 root 运行、上传持久卷、健康检查、SIGTERM、只读根文件系统和受限临时目录；真实 Linux 文件边界与全部后端检查。Rust、Java 比较使用相同 Linux 环境与资源限制。
2. **已有库接管**：显式命令先核对 6 张业务表、列类型/空值/默认值/identity、主外键与唯一约束、PostGIS 和迁移记录；兼容时登记原始基线的真实 SQLx checksum，绝不重复建表或改写业务数据。缺失或不兼容则失败。检查、登记和并发控制为明确的原子过程；普通启动仍只读校验。重复账号只报告数量，不自动合并、改名或删账号。
3. **升级与回退演练**：PG 17 的合成旧库导出到 PG 18，核对表和媒体指纹、序列；Java 先在新库工作，切到 Rust 产生用户、点位、译文、图片和收藏，再切回 Java 验证这些新增数据、身份与媒体仍可用。一次只向一个后端转发写请求；切换清楚处理新旧 session 与重新登录。数据库版本回退须在写入冻结后导出包含新增写入的最新数据并恢复核对，不能恢复旧快照丢弃新增数据。
4. **性能与客户端**：固定合成数据、硬件配额、缓存状态、哈希成本和并发，记录 idle/warm/read/login/upload 场景的进程 RSS、容器内存、CPU、P50/P95、错误率和 PG 连接数。Rust 使用 release、Java 正常 JAR 并预热，避免将 debug 或启动编译开销算作服务性能。Web 真实浏览器流程；移动端用现有客户端逻辑及测试覆盖，设备运行能力单独据实记录。

### 发布运行参数补齐

HTTP 超时不会自动保证数据库语句或阻塞任务已经停止。阶段 4 为服务连接增加显式 `DB_STATEMENT_TIMEOUT_MS`（默认 20,000 ms）与 `DB_LOCK_TIMEOUT_MS`（默认 5,000 ms）；正值且有界，不允许无意关闭超时。SQL 语句超时映射为受控服务不可用响应，事务失败后回滚，不把已提交写入改报为可重试失败。真实 PostgreSQL 测试使用短 `pg_sleep` 和锁竞争证明参数生效及连接可复用。维护命令使用独立连接策略，不继承服务的 20 秒语句限制；迁移与接管锁仍有明确等待上限。

密码计算增加 `PASSWORD_MAX_CONCURRENCY`：默认按可用 CPU 数取 1～4，允许显式配置 1～32；图片并发继续使用已有配置。两者的许可均由实际阻塞任务持有至结束，保留请求取消后的并发上限。性能报告记录最终配置，不能仅依据环境变量的预期值推断结果。

## 阶段 5 设计方向

- 维持当前球面距离语义：地球半径 `6,371,000 m`，与 Web/App 的 Haversine 显示一致；SRID 使用 4326，输入是经纬度角度，经度在前、纬度在后。先核对客户端坐标来源，不把 GCJ-02 当成 WGS84 转换。
- 增量迁移增加 `geography(Point,4326)` 的 **STORED generated column** 与 GiST 索引。生成列从合法经纬度派生，使 Java 回退期间的写入也自动更新空间值；旧列仍为写入入口，不增加两套应用写同步逻辑。不修改已发布的 `0001_baseline.sql`。
- 无法直接表示为合法 geography 的历史坐标保留原值，不通过 PostGIS 隐式归一改写。对有限的历史异常值保留明确兼容查询路径；非有限值处理依据已有行为和独立测试定案。
- `ST_DWithin(..., false)` 利用空间索引筛出保守候选，最终沿用原有 `6371000 * 2 * asin(sqrt(...))` Haversine 公式筛选与 `distance, id` 排序。温晓在 PostGIS 3.6.4 上实测赤道 1°：指定半径的 `ST_DistanceSphere` 为 `111194.92664455874 m`，默认 geography 球面距离为 `111195.07973463 m`，证明不能直接用原半径做候选范围。
- 对固定 WGS84/SRID 4326，候选半径采用 `radius * 1.002 + 0.01 m`：WGS84 最大半轴 `6378137 m` 与产品球半径的比值小于 `1.002`，该范围保守覆盖目标球面范围；最终仍按原半径准确筛选，不扩大用户结果。坐标来源遵循现有客户端约定，不凭数值推断或转换历史数据的坐标系。
- 合法空间行与历史异常坐标用明确的 `UNION ALL` 两条路径，避免一个跨分支 `OR` 使空间索引失效。历史有限但超范围的坐标仍按原公式处理，不改写；NaN/Infinity 不参与附近结果，预检只报告数量。必要时对无空间位置的历史行使用小型部分索引，实际执行计划决定。距离公式的浮点极值保护与恰好边界行为必须有回归证据。
- 保持附近查询 1～50,000 m 参数语义和既有返回规模；视口矩形语义另行验证，日期变更线、极点、恰好边界、同距离排序、类别及可见性必须覆盖。缓存键版本区分新旧查询，提交后失效规则保持。
- 采用公开可重复的合成数据分布与不同规模，保存 `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`，证明目标负载实际使用索引并比较旧查询、新查询的结果与延迟。收益不足时先诊断分布/计划，不以关闭 seqscan 强迫索引来宣称优化。

上述设计依据：[PostGIS ST_DWithin](https://postgis.net/docs/ST_DWithin.html)、[ST_DistanceSphere](https://postgis.net/docs/ST_DistanceSphere.html)、[PostgreSQL 生成列](https://www.postgresql.org/docs/current/ddl-generated-columns.html)、[Docker 多阶段构建](https://docs.docker.com/build/building/multi-stage/)。精确候选范围、镜像 digest、测量结果与最终验收另行记录。

## 已完成范围

- 桌面和平板：Contribute 显示原稿选点提示，点击地图后打开原稿贡献表单；键盘 Enter 可选地图中心。
- 手机：保留右侧画笔，点击即取当前地图中心并打开表单。桌面选点时切为手机，以及账号重置后仍打开的手机表单，都能正确取得新草稿中心；已有坐标和编辑坐标不被覆盖。
- Title、三类 Category、Description、成对营业时间、可选 Photo 与 Submit 连接真实 Rust 接口。无新增公开/私有控件；新建采用公开默认值，编辑保留数据库中的原值。
- 新建的 UUID 与首次提交内容一起冻结。丢失响应后重试同一请求；即使后续恢复得到 4xx，也不会把新内容错误绑定到旧 UUID。
- 先保存点位，再上传图片。图片失败不会重复创建点位；图片只形成待审核提案。未登录时保留草稿，登录后继续原操作。
- 编辑沿用贡献表单，固定已有坐标，保留实际内容语言，不回写计算得到的 isActive。纯图片修改不创建无意义的文字提案。普通 PATCH 返回当前点位，成功提示明确为待审核。
- 关闭表单后后台上传继续，再点贡献入口会打开同一任务。退出、账号切换和整个 Provider 卸载会取消后续客户端操作并清空草稿。

## 最小 Rust 续传协议

新增迁移 `0003_marker_image_uploads.sql`，没有修改历史迁移；原整图上传接口保持兼容。

| 方法 | 路径（前缀 `/api/markers/{id}`）            | 行为                                                         |
| ---- | ------------------------------------------- | ------------------------------------------------------------ |
| POST | `/image-uploads`                            | `clientRequestId`、`totalBytes`、`sha256` 创建或恢复同一会话 |
| GET  | `/image-uploads/{uploadId}`                 | 返回已确认字节数与完成状态，`Cache-Control: no-store`        |
| POST | `/image-uploads/{uploadId}/chunks/{offset}` | `application/octet-stream`，固定 256 KiB 分片，末片可较短    |
| POST | `/image-uploads/{uploadId}/complete`        | 校验 SHA-256、解码并建立一次待审核图片提案                   |

回执字段：`uploadId`、`markerId`、`totalBytes`、`receivedBytes`、`chunkSize`、`status`。会话绑定账号和点位，每条路由检查身份及点位可见性，不暴露未审核图片 URL。

- PostgreSQL 在同一事务中保存分片和 offset；已收到的重复分片比对字节，不重复追加。
- 最大图片 5 MiB，沿用 JPEG/PNG/GIF/WebP、尺寸和像素数限制。每账号最多 4 个有效会话、20 MiB 预留空间。未完成会话 24 小时过期。
- 创建会话前使用独立短事务批量回收最多 32 条过期暂存数据；完成或过期记录保留，旧 UUID 不被复用。完成后清空暂存 bytea。
- 完成操作以会话行锁串行化；提案与完成回执同事务提交。最多 4 个后台完成任务，HTTP 等待取消后继续收尾。提交前明确失败会清理新文件；COMMIT 结果不明时保留文件，避免删除可能已被引用的图片。
- 浏览器每次失败先查已确认 offset；网络/408/5xx 在后台退避重试，最长间隔 30 秒，浏览器明确离线时等待 online。等待不占 Cookie 会话锁，恢复后只发送剩余字节。
- 浏览器未知回执保留同一图片 UUID；只有明确拒绝文件时才允许更换或移除。文字 PATCH 仍没有后端幂等接口，因此响应不明时保留显式重发确认，不伪装成可安全自动重试。

续传文件和客户端请求标识保存在本次页面会话中：关闭侧栏可继续；刷新页面、关闭标签页或退出账号后，不自动恢复本地文件。服务端已确认分片可跨服务重启恢复；未完成会话的 24 小时窗口和磁盘/数据库在进程崩溃时的非原子边界仍需后续运维维护。
